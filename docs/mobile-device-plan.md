# DocuDog 모바일 기기 계획 (구현 보류)

**상태:** 계획 전용 — 현재 구현하지 않는다.  
**작성일:** 2026-09-04  
**범위:** PC 중심 Stage 1 Watcher를 유지하면서, 향후 Android/iOS 및 로컬 LLM 가능 스마트폰에서 제공할 최소 기능과 기술 경계를 정한다.

## 1. 제품 판단

DocuDog의 현재 강점은 PC에서 사용자가 평소처럼 파일을 저장하면, 유휴 시간에 추출·분류·감사·계보를 조용히 처리하는 흐름이다. 모바일은 파일 시스템을 지속 감시하는 PC 워처를 그대로 옮기는 제품이 아니다.

모바일의 1차 역할은 다음으로 한정한다.

- 공유 메뉴 또는 파일 선택으로 사용자가 명시적으로 보낸 문서를 수집한다.
- 텍스트 PDF와 사진·스캔 문서에서 로컬로 텍스트를 얻는다.
- 짧은 텍스트에 대해 요약·태그·P등급을 로컬 LLM으로 보조한다.
- 최근 처리 문서, 보안 경고, 검색 결과를 짧게 확인한다.

원본 자동 이동, 클라우드 자동 업로드, 이메일/메신저 차단, 백그라운드 전체 저장소 감시는 모바일 범위에 넣지 않는다.

## 2. Docling 적용 판단

Docling은 PC의 선택형 고급 추출 엔진 후보로 검토한다. 스캔 PDF OCR, 표·레이아웃 구조, 문단 위치 정보를 확보해 이후 의미 검색의 근거 위치를 개선할 수 있다.

하지만 Docling 전체 Python/PyTorch 스택을 Android/iOS 앱에 직접 포함하지 않는다.

- 공식 배포의 주 대상은 macOS·Linux·Windows이며 Android/iOS 네이티브 SDK가 아니다.
- PDF 파서·OCR·모델 의존성은 앱 크기와 RAM 사용량을 크게 만들며, Android ARM Python 환경의 빌드·native parser 안정성도 제품 수준으로 확인되지 않았다.
- 모바일에서 필요한 기본 추출은 플랫폼 네이티브 API가 더 작고 안정적이다.

따라서 **PC에서는 Docling을 선택 기능으로 검증**하고, **모바일에서는 네이티브 PDF/OCR 파서**를 사용한다. 복잡한 표 복원·레이아웃 이해·대용량 스캔 처리는 사용자가 명시적으로 PC 동반 처리로 넘기는 후속 범위다.

## 3. 목표 사용자 흐름

1. 사용자가 스마트폰의 파일 앱·공유 메뉴에서 PDF/사진을 DocuDog으로 보낸다.
2. 앱은 텍스트 레이어가 있는 PDF에서 텍스트를 우선 읽고, 없으면 사용자가 허용한 경우에만 온디바이스 OCR을 수행한다.
3. 기기 내 경량 모델이 짧은 텍스트를 요약하고 태그·P등급 초안을 만든다.
4. 사용자는 분류 결과와 P1/P2 주의 문구를 확인·수정한다.
5. 앱은 원본 위치, 추출 결과, 분류 메타를 기기 내 저장소에 기록한다. PC와의 연결 기능은 자동 동기화가 아니라 사용자가 선택한 LAN/USB 내보내기로 별도 검토한다.

## 4. 기능 단계

### M0 — 설계·검증만

- Android/iOS 각각에서 지원할 최소 OS 버전, 로컬 LLM 런타임, PDF/OCR API를 조사한다.
- 한국어 텍스트 PDF·사진 문서·스캔 PDF fixture와 대표 질의셋을 만든다.
- 문서 한 건당 처리 시간, 배터리 소모, 메모리 피크, 앱 추가 용량, OCR 품질을 측정 기준으로 확정한다.
- P1/P2 원문·발췌가 검색/공유/알림에 노출되지 않는 정책을 설계한다.

### M1 — 네이티브 수동 수집·경량 분류

- Android 공유 인텐트 및 iOS Share Extension으로 명시적 파일 수집.
- 텍스트 PDF 추출, 이미지/스캔 OCR, 실패 사유와 재시도 안내.
- 기기 내 짧은 요약·태그·P등급 초안 및 사용자 수정.
- 최근 처리 목록과 P1/P2 알림. OS 제약을 준수하고 지속 감시는 하지 않는다.

### M2 — 로컬 검색·PC 동반 처리

- 모바일에서 생성된 P3/P4 메타데이터와 짧은 근거 청크의 로컬 검색.
- 대형·복잡 문서를 PC DocuDog으로 **사용자 승인 아래** 전송하는 LAN/USB 내보내기 실험.
- PC가 처리한 결과를 사용자가 선택해 모바일에 가져오는 읽기 전용 digest.

### M3 — 보류 항목

- 모바일 백그라운드 전체 폴더 감시.
- 자동 클라우드 동기화 및 원본 서버 업로드.
- 모바일에서의 Docling 전체 번들·대형 VLM 탑재.
- 메일·메신저·외장 저장소 수준의 실시간 DLP 차단.

## 5. 기술 원칙

- **로컬 우선:** 문서·질의·임베딩은 기본적으로 기기를 벗어나지 않는다. 원격 모델·PC 전송은 목적과 대상을 고지한 명시적 opt-in만 허용한다.
- **경량 우선:** PDF 텍스트 레이어 → 네이티브 OCR → 선택형 로컬 LLM 순서로 비용이 낮은 경로를 먼저 사용한다.
- **정책 우선:** P등급 판단과 allowlist를 추출 결과의 저장·검색·공유 이전에 적용한다. P1/P2는 기본적으로 원문·근거 청크를 인덱스와 알림에서 제외한다.
- **원본 보존:** DocuDog은 원본 파일을 자동 이동·삭제·수정하지 않는다.
- **PC와 역할 분리:** PC는 대량 감시·고급 추출·계보·감사, 모바일은 명시적 수집·빠른 확인·경량 분류를 담당한다.

## 6. 구현 착수 조건

다음이 충족되기 전에는 구현을 시작하지 않는다.

- M0 fixture에서 한국어 OCR·분류 품질과 P1/P2 차단 동작을 재현 가능하게 검증한다.
- 대표 기기에서 처리 시간·배터리·메모리·앱 크기가 사용성 목표를 충족한다.
- 모바일 저장소 암호화, OS 권한, 공유 확장, PC 전송 동의의 보안 설계를 검토한다.
- PC Stage 1의 watch settle, MCP 컨텍스트 팩, 선택형 Zvec 의미검색 등 우선 백로그와 충돌하지 않음을 확인한다.
