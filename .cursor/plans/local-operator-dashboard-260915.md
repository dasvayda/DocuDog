## 1. 왜 이 고민이 나오는지

백그라운드 설계의 장점: 타이핑 중에 안 막고, 폴더 규칙을 안 강요하고, Cursor에서 자연어로 물으면 됨.

한계는 “조용함”이 **안 보이는 것**과 같다는 점임.

| 사람이 하고 싶은 일 | 지금 | 막히는 지점 |
|---------------------|------|-------------|
| 오늘 돌아가고 있나 | 트레이 아이콘, 로그, `DocuDog_status.md` | status는 `.docudog/` 안. 트레이는 **열지 않음**. 초보는 “죽은 건지 일하는 건지” 모름 |
| P1이 뭐였지 | 토스트 한 번 + audit MD | 지나간 토스트는 사라짐. MD를 찾을 줄 알아야 함 |
| 이 파일들이 한 과제인가 | MCP `thread` / lineage | **Cursor를 안 쓰는 사람**에게는 입구가 없음 |
| A, B, C 골라 인수인계 초안 | Compose CLI (`260915-01`) | 경로/`file_id`를 손으로 넣는 건 실무에서 거의 안 함 |
| MCP·모델이 붙었나 | 설정 파일, 로그 | `260910-03`·`05`가 트레이 마법사를 예정. 화면이 없으면 카드 UI를 둘 곳이 없음 |

정리하면: **코파일럿이 있는 지식 노동자**에게는 MCP가 주 입구로 맞음.  
**코파일럿 없이 설치만 한 사람**, 그리고 **파일을 골라서 제3 문서를 만드는 일**에는 백그라운드+CLI만으로 구멍이 남.

이미 있는 `DocuDog_status.html`은 “대시보드”에 가깝지만 **스냅샷 파일**임. 버튼이 없고, 강제 오픈도 없고, 최신인지도 브라우저 새로고침에 달림.

## 2. 넣을지 판단

### 필요한 것 (좁은 의미의 로컬 페이지)

**운영 콘솔:** “개 잘 있나 / 오늘 뭐 했나 / 민감한 것만 다시 보기 / (나중에) 이 목록에서 골라 보고서 만들기”

이건 Organizer Fatigue가 아님. 태그를 매일 달라는 화면이 아니라, **이미 붙은 라벨을 훑는 화면**임. Notion 대체도 아님.

대상 사용자:

- Cursor를 안 켜고 Word/한글만 쓰는 동료
- 본인이 코파일럿을 써도, Compose 때 **체크박스가 필요한** 순간
- 설치 직후 “초록/빨강”을 눈으로 확인하고 싶은 순간 (`260910-05`와 맞닿음. 다만 **온보딩 전용 웹 마법사는 여전히 비권장** — 첫 실행은 트레이가 맞고, 대시보드는 **켠 다음** 여는 화면)

### 필요 없는 것 (넓은 웹앱)

- 코퍼스 전체 탐색기, 그래프 클릭, 백링크, 태그 클라우드 편집기 → `260910-D`와 같음
- 인터넷에 열리는 서버, 계정, 팀 실시간 보드
- DocuDog 자체 채팅창 (`260910-04`가 이미 금지)
- status.md를 시작할 때마다 강제 오픈 (피봇 때 일부러 뺌. 작업 방해)

### 결론

**조건부 채택: 로컬(127.0.0.1) 운영 대시보드.**  
PKM 웹앱은 거절. 1차는 읽기 + 아주 적은 동작. Compose 선택 UI는 엔진(`260915-01`) 다음에 이 페이지의 한 섹션으로.

사용성: Cursor 사용자만 보면 우선순위가 중간. **팀 배포·Compose·“돌아가는지”**까지 보면 중간~높음. 백그라운드만 고집하면 Compose는 문서에만 남고 손이 안 감.

## 3. 이미 있는 것과 역할 분담

| 표면 | 역할 | 대시보드가 가져가면 안 되는 것 |
|------|------|-------------------------------|
| Watcher | 수집·분류 | 그대로. UI가 워처를 대체하지 않음 |
| 트레이 | 항상 켜진 작은 손잡이 | 메뉴는 유지. **「Open dashboard」** 한 줄만 추가하면 입구가 생김 |
| `DocuDog_status.html` | 정적 현황 | 내용의 원천. 대시보드 1차는 이 HTML을 브라우저로 여는 것부터 |
| MCP | 채팅·에이전트 | 질의·최신본·context_pack의 **주 경로 유지** |
| Compose CLI | 파일 생성 엔진 | UI는 선택만 하고, 생성은 같은 엔진 호출 |

한 문장: **에이전트는 MCP, 사람은 로컬 한 페이지, 개는 백그라운드.**

## 4. 화면을 쪼개는 법 (작업 가능한 범위)

한 페이지, 스크롤 구간만. 라우팅 SPA 없음.

1. **건강** — 실행 중/일시정지, 마지막 분류 시각, 백엔드(mock이면 크게 표시), 워치 폴더 몇 개, MCP ping 초록/빨강. 실패는 한 줄.
2. **오늘** — status와 같은 숫자: 오늘 건수, P1/P2, 할 일(action digest), 미분류 경고.
3. **최근 대화** — 스레드 Top N, 펼치면 멤버. 원본 경로를 탐색기에서 열기(선택).
4. **민감** — P1/P2 **제목·경로·한 줄**만. 본문 없음. audit와 같은 정책.
5. **만들기 (2차)** — 최근 분류 또는 한 스레드에서 체크 → intent 텍스트 → MD 저장. `260915-01` 엔진. 폴더 트리 브라우저는 없음.

비목표 화면: 설정 JSON 에디터(고급은 파일), 태그 일괄 편집 그리드, lineage Mermaid 전체, 사용자 계정.

## 5. 구현 사다리 (쉬운 것부터)

| 단계 | 무엇 | 왜 먼저 |
|------|------|---------|
| **0** | 트레이 「Open status page」→ 이미 있는 `DocuDog_status.html` | 공수 최소. “정적 HTML로 충분한지” 실사용으로 검증. 피봇의 ‘강제 오픈 금지’는 유지(메뉴로만) |
| **1** | status HTML을 조금 읽기 쉽게 (고정 머리글: 건강 3줄). 여전히 파일 | 서버 없이 대시보드 느낌 |
| **2** | loopback만 듣는 작은 HTTP (`127.0.0.1`, 포트 고정, 외부 NIC 바인드 금지). 페이지는 서버가 status/state를  squirt | 새로고침하면 최신. 일시정지 토글 정도는 POST |
| **3** | Compose 체크리스트 섹션 | `260915-01` 이후 |
| 보류 | React/Vite, 원격 URL, 모바일 반응형 앱 | 운영 콘솔 범위를 넘는 순간 중지 |

단계 0에서 “아무도 안 연다 / 열어도 부족하지 않다”면 단계 2를 미룸.  
“골랐으면 좋겠다 / 살아 있는지 버튼이 필요하다”가 나오면 단계 2.

기술 메모:

- 기존 `classification_report.html` 변환 유틸·스레드 `<details>`를 재사용.
- 원격 MCP HTTP(`8765`)와 **포트를 섞지 않는 편**이 안전함. UI는 예: `8766` 또는 `dashboard_settings.port`. Bearer는 loopback-only면 1차는 생략 가능하나, P1 제목이 있으므로 **기본은 loopback + 로컬만**.
- 워치 루트에 HTML을 쓰지 않음. artifact_home.
- Windows에서 브라우저 기본 앱으로 열기: `webbrowser.open`.

## 6. 성공 / 실패 기준

성공: Word만 쓰는 사람이 트레이에서 페이지를 열고, 오늘 개수와 P1 목록을 이해함. Cursor 사용자는 이 페이지 없이도 MCP로 일 할 수 있음.

실패로 볼 신호: 태그 편집·그래프·전체 검색창을 이 페이지에 넣기 시작함. 시작 시 브라우저가 강제됨. 대시보드가 MCP를 대체한다고 문서에 적힘.

## 7. `260910-05`와의 관계

제로설정은 **트레이 마법사**가 맞음 (폴더 프리셋, 샘플 1건, ping). 웹 온보딩 위자드는 여전히 비권장.

대시보드는 마법사가 끝난 뒤 “다시 보는 현황판”. ping 초록을 트레이와 **같은 문구**로 보여 주면 됨.
